# 06 · 数据层：知识库清洗与切分

对应代码：`agentkit/data/`，测试：`tests/test_data.py`。

## 1. 清洗：七步，每步计数

RAG 效果差，一半以上在数据：重复文档把 top-k 占满、页眉页脚进了向量、全角半角混排检索不命中、新旧版本并存互相矛盾。`cleaning.py::clean_documents` 的顺序：

| 步 | 做什么 | 为什么 | 计数字段 |
|---|---|---|---|
| 1 归一化 | Unicode NFKC（全角→半角）、统一换行、去零宽字符、压缩空白 | "ＡＢＣ　１２３" 和 "ABC 123" 必须是同一个东西 | — |
| 2 模板噪声 | 在 ≥50% 文档里出现的行（导航、版权、"点击查看更多"）整行删除 | 这些行会成为每个 chunk 的公共前缀，检索时到处命中 | `boilerplate_lines`, `boilerplate_removed` |
| 3 空文档 | 删 | — | `dropped_empty` |
| 4 过短文档 | < min_chars 删 | 一句话的文档通常是目录页、占位页 | `dropped_short` |
| 5 精确去重 | sha256 | 同一篇被爬两次 | `dropped_exact_dup` |
| 6 近似去重 | 5-shingle Jaccard ≥ 0.85 | 同一篇文章的两个版本（多了个"（2026 年版）"） | `dropped_near_dup` |
| 7 PII 脱敏 | 复用 `guard/content_filter.py` 的规则 | 知识库里不该有用户手机号 | `pii_redactions` |

`CleanReport` 记录每一步删了多少。清洗不是黑盒，"删了多少、为什么删"必须能回答（`test_clean_pipeline_reports_every_decision`）。

元数据要保留：来源、更新时间、版本、内容哈希。检索时按时间过滤、给模型引用、发现新旧版本冲突都靠它。

## 2. 切分：三种策略，各自的问题

| 策略 | 做法 | 优点 | 缺点 | 函数 |
|---|---|---|---|---|
| 固定长度 + 重叠 | 每 N token 一块，块间重叠 M | 简单稳定，任何文本都能切 | 会把一句话切成两半；重叠补这一刀 | `chunk_fixed` |
| 递归分隔符 | 段落 → 句子 → 词，尽量在语义边界切；超长再退到固定切 | 块内语义完整 | 块大小不均；表格会被切散 | `chunk_recursive` |
| 结构感知（Markdown） | 按标题切；标题路径写进元数据；长节内部再递归；父子块 | 检索命中"退款政策 > 特殊情况"比命中一段裸文本有用；小块检索、父块喂模型 | 依赖文档有结构 | `chunk_markdown` |

父子块：`chunk_markdown` 每节生成一个 `role=parent` 的整节块，节内超长再切成 `role=child` 的小块，`meta.parent_id` 指向父块。检索用子块（精准），给模型喂父块（完整上下文）。子块文本前缀带标题路径，向量里也有结构信息（`test_markdown_chunks_carry_heading_path_and_parent_child`）。

## 3. 选哪种、多大：用评估说话

没有万能 chunk size。方法：
1. 准备一组真实问题 + 标注的命中段落（几十条就够起步）；
2. 对每种策略 × 每个 size 建索引，算 recall@k（k = 你打算喂给模型的块数）；
3. 兼顾块大小：块越小召回越准但上下文越碎，模型拿到的信息不完整；一般 200–500 token 起步。

还要看的失败模式：
- 表格被切散（表头和数据行分家）→ 表格单独成块或转成"表头: 值"的句子；
- 标题丢失（正文块不知道自己属于哪一节）→ 结构感知 + 标题前缀；
- 代码块 / 列表被切断 → 在分隔符列表里把 ``` 和列表项当作不可切的整体；
- 中英混排 → token 估算要按字符类型分别算（`tokens.py` 里 CJK 按字计）。

## 4. 面试时的一句话版本

"清洗按固定顺序：归一化、去模板噪声、去空去短、精确和近似去重、脱敏，每一步计数可解释，元数据留版本和时间；切分默认结构感知父子块，小块检索父块喂模型，chunk 大小用标注问题的 recall@k 选，不拍脑袋。"
