# 05 · 工作流编排：状态机、节点重试、分支回滚

对应代码：`agentkit/workflow/`，测试：`tests/test_workflow.py`，示例：`examples/04_workflow_refund.py`。

## 1. 为什么是状态机不是线性 Chain

| 需求 | 线性 Chain | 状态机 |
|---|---|---|
| 根据中间结果走不同路径 | 只能在节点里塞 if | 边可以是 `state -> next_node` 的函数 |
| 某一步失败重试，别的步不动 | 整条重跑 | 节点级 `retry` 策略 |
| 某一步失败要撤销前面的副作用 | 没有语义 | Saga 补偿（`compensate`） |
| 非关键步失败不影响主流程 | 抛异常整条断 | `optional` 节点只标记 degraded |
| 进程崩了从断点继续 | 从头来 | checkpoint + `resume` |
| 回到某一步（补充信息后重判） | 做不到 | 边指回去 + 流转上限防死循环 |
| 每一步的耗时、重试、结果可观测 | 要自己加 | 每个节点一条 `workflow.node` 事件 |

一句话：Chain 只有"下一步"，状态机把"这一步失败了该怎么办"变成节点上的显式属性。

## 2. 节点的属性（`state_machine.py::Node`）

```python
Node(name, run, retry=NO_RETRY, compensate=None, optional=False, timeout_s=None)
```

- `run(state) -> dict`：返回要合并进 state 的字段；抛异常表示失败，异常上的 `retryable` 决定能不能重试（复用工具层的错误分类）。
- `retry`：与工具层同一个 `RetryPolicy`（指数退避 + 抖动）。
- `compensate(state)`：回滚动作。
- `optional`：失败不终止流程。
- `timeout_s`：与工具层同一个 `run_with_timeout`。

边：`wf.add(node, next)`，`next` 是节点名或 `lambda state: 节点名`，`END` 结束。

## 3. 分支判定

```python
def route_after_check(state):
    if not state["eligible"]:
        return "reject"
    return "auto_refund" if state["amount"] <= 100 else "manual_review"
```

判定逻辑是纯函数，只看 state，可以单独测；`test_branch_to_manual_review_for_large_amount`、`test_branch_reject_when_not_eligible`。

## 4. 分支执行失败怎么回滚：Saga 补偿

退款流程：`validate_order → check_eligibility → auto_refund → update_inventory → notify_customer`。

`auto_refund` 已经记账，`update_inventory` 永久失败。此时：
1. runner 收集"已完成且有 compensate 的节点"（`completed_with_effects`）
2. 逆序执行补偿：`auto_refund.compensate` 写一条冲正记录
3. 结果状态 `compensated`，`compensated=["auto_refund"]`（任一补偿失败则状态为 `compensation_failed`）

三个要点：
- **补偿是冲正不是删除**：账本里是 `refund` + `reversal` 两条（`test_required_node_failure_compensates_completed_side_effects`），账务不可篡改，审计能看到发生过什么。
- **补偿失败必须在结果上看得出来**：补偿也可能失败（下游也挂了）。runner 发 critical `alert`，结果状态是 `compensation_failed`，`compensated` / `compensation_failed` 两个列表分别列出成功和失败的节点（`test_compensation_failure_is_visible_on_result_and_alerts`）。只告警不改状态的话，"全部补偿失败"和"没什么可补偿"在结果上长得一样。
- **补偿也要幂等**（生产要求，本项目未实现）：重试补偿、或恢复后再次触发补偿时不能重复冲正。做法是补偿动作带上原操作的幂等键，冲正记录按键去重。

## 5. 防止单点故障拖垮整条链路

- `notify_customer` 是 `optional`：通知失败不能让退款失败。`test_optional_node_failure_only_degrades`：status 仍是 completed，`degraded=["notify_customer"]`，账本正常。
- 节点超时：一个慢下游不能挂住整个流程。
- `max_transitions`：边判定写出环时有界失败（`test_edge_loop_is_bounded`）。
- 节点级重试只重试可重试的异常：业务拒绝不会被重试三次。

## 6. checkpoint 与恢复

每个节点**成功后**写 checkpoint（state、下一个节点、路径、已完成的有副作用节点、降级列表、尝试次数）。进程崩了（`test_resume_from_checkpoint_after_crash` 用 `SystemExit` 模拟，它不是 `Exception` 子类，不会被重试/补偿逻辑捕获），`resume(run_id)` 从 `next` 继续，`auto_refund` 不会再执行一次——账本里只有一条退款。

注意 checkpoint 存储在示例里是内存实现；生产要落数据库，且 checkpoint 写入与节点副作用最好在同一事务或用 outbox。

## 7. `examples/04_workflow_refund.py` 的七个场景

1. 小额自动退款：全路径 completed
2. 大额走人工审核：分支到 manual_review，生成工单
3. 金额超订单金额：分支到 reject
4. 校验订单两次 503：`attempts["validate_order"] == 3`，completed
5. 库存更新永久失败：compensated，账本 refund + reversal
6. 通知失败：completed 且 degraded
7. 进程被杀：checkpoint next=update_inventory，resume 后完成，账本只有一条

## 8. 面试时的一句话版本

"状态机让'这一步失败了怎么办'变成节点属性：节点级重试只重试可重试异常，分支边是纯函数，必需节点失败逆序执行 Saga 补偿（冲正不是删除，补偿失败告警），可选节点失败只降级，节点成功后写 checkpoint 崩了从断点续跑不重复副作用。"
